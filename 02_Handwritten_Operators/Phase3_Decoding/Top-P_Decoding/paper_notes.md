### 论文总结

这篇论文 **《The Curious Case of Neural Text Degeneration》**（Holtzman et al., ICLR 2020）讨论的是：

> **为什么神经语言模型明明很强，但一旦用常见解码方法生成长文本，结果却常常变得重复、空洞、甚至胡言乱语？**

作者的核心结论是：**问题不主要在模型本身，而在解码策略（decoding strategy）**。他们提出了一种新的方法：**Nucleus Sampling（核采样，top-p sampling）**，并证明它比 beam search、纯采样、top-k sampling 等方法更适合开放式文本生成。

***

### 1. 研究背景

神经语言模型通常按“下一个词的概率”训练，即最大化文本似然。但作者发现：

*   **最大化概率的解码方法**（如 greedy search、beam search）

往往生成：

*   重复
*   乏味
*   套话化
*   陷入循环
*   **直接按完整分布随机采样**（pure sampling）

又容易生成：

*   不连贯
*   偏离上下文
*   胡言乱语

也就是说：

*   **追求最高概率** → 太保守，文本退化成重复模板
*   **完全随机采样** → 太开放，容易采到低质量尾部词

***

### 2. 论文的核心观点

作者提出三个关键判断：

1.  **最大化并不是开放式文本生成的合适目标**
2.  **语言模型预测分布的低概率尾部（tail）不可靠**
3.  **最好的策略是截断这个不可靠尾部，再进行采样**

这就是他们提出 **Nucleus Sampling** 的动机。

***

### 3. 什么是 Nucleus Sampling？

#### 定义

对于每一步生成，模型会给词表中每个 token 一个概率。\
Nucleus Sampling 不固定取前 $k$ 个词，而是：

*   按概率从高到低排序
*   选出**累计概率刚刚超过阈值 $p$** 的最小词集合
*   只在这个集合中采样

形式上，论文定义 top-$p$ 词集 $V^{(p)}$ 为：

$$
\sum_{x \in V^{(p)}} P(x \mid x_{1:i-1}) \ge p
$$

然后只在这个集合上重新归一化采样。

#### 直观理解

*   如果当前上下文下模型很确定，可能只需几个词就能覆盖 95% 概率质量
*   如果当前上下文不确定，则候选集合会自动变大

因此它的优势是：

*   **不像 top-k 那样候选数固定**
*   **能动态适应不同上下文的不确定性**
*   **避免把低概率尾部中不可靠的词采进来**

***

### 4. 为什么 beam search 会退化？

论文强调了一个非常反直觉的事实：

> **人类写出的自然文本，并不是模型概率最高的文本。**

原因包括：

#### 4.1 高概率不等于高质量

beam search 会偏向：

*   最常见表达
*   最安全续写
*   最不出错的重复结构

结果是文本虽然局部概率高，但整体很机械。

#### 4.2 重复会形成“正反馈”

论文图 4 展示：

*   一旦模型开始重复某个短语
*   这个短语再次出现的概率会不断升高
*   最终陷入循环

比如：

*   “the current state of the art ...”
*   重复多次后越来越难停下来

#### 4.3 自然语言本身不追求“每个词都最可预测”

作者借用了 **Grice 的交际准则** 解释：

*   人类说话/写作不会总是选择最平庸、最可预测的词
*   否则信息量太低，表达就会显得空洞

因此，“逐词最大化概率”本身就和自然文本分布不一致。

***

### 5. 为什么 pure sampling 也不好？

纯采样的问题在于：

*   从整个词表分布采样
*   即使尾部单个词概率很小，但词很多
*   累积起来会频繁采到“不靠谱”的 token

作者称这部分为 **“unreliable tail”**（不可靠尾部）。

后果：

*   语义漂移
*   不连贯
*   生造词
*   上下文断裂

因此，**纯采样比 beam search 更自由，但也更容易失控**。

***

### 6. top-k sampling 为什么不够好？

top-k 的做法是每步固定从前 $k$ 个词中采样。

论文认为它比 beam search 和 pure sampling 都好，但仍有缺陷：

#### 问题：固定

$k$ 不适合所有上下文

不同上下文下，模型分布形状差异很大：

*   有时分布很平：很多词都合理
*   有时分布很尖：少数词占绝大多数概率

于是：

*   **$k$ 太小** → 容易过于保守，生成平淡文本
*   **$k$ 太大** → 会把不合适的尾部词带进来，降低连贯性

所以作者认为：\
**固定 $k$ 的截断方式是静态的，不如 top-p 的动态截断合理。**

## beam search是什么？top-k解码在截断k之后的token之后,会在剩余未截断的token中重新归一化采样吗？

***

会。论文里 **top-k** 和 **nucleus(top-p)** 都是：**先截断，再对保留下来的概率重新归一化，然后采样**。

***

### 1) Beam search 是什么？

**Beam search（束搜索）** 是一种**近似最大化概率**的解码方法。

语言模型生成文本时，每一步都会给出下一个 token 的概率分布。\
如果用 **greedy search**，每一步只选当前概率最大的那个 token。\
但这样容易局部最优，所以 beam search 会**同时保留多个候选前缀**。

#### 基本过程

设 beam width 为 $b$：

1.  第一步，找出概率最高的  $b$  个 token，作为  $b$  条候选序列

2.  之后每一步：

*   对当前每条候选序列继续扩展若干个可能 token

*   计算每个扩展后序列的累计分数（通常是对数概率和）

*   从所有扩展结果里保留总分最高的  $b$  条

3.  重复直到生成结束

#### 直觉

它不是“随机生成”，而是在找：

$$
\arg\max_{x_{m+1:m+n}} P(x_{m+1:m+n}\mid x_{1:m})
$$

也就是尽量找**整体概率最高**的续写。

#### 这篇论文为什么批评 beam search？

因为在**开放式文本生成**里，最高概率续写往往不是最自然的，而是：

*   很安全
*   很模板化
*   容易重复
*   容易陷入循环

论文中的 Figure 1、Figure 2、Figure 3 都展示了这种现象。

***

### 2) top-k 解码是什么？

top-k sampling 的做法是：

*   每一步先按概率从高到低排序

*   只保留前  $k$  个 token

*   其余 token 概率直接置 0

*   **在这 $k$ 个 token 上重新归一化**

*   然后从归一化后的分布中随机采样

***

### 3) 你的问题：截断后会重新归一化吗？

**会，明确会。**

论文第 **3.2节 Top-k Sampling** 写得很清楚：

> At each time step, the top $k$ possible next tokens are sampled from according to their relative probabilities.

并且定义：

*   $V^{(k)} \subset V$  是 top- $k$  词表

*   $p' = \sum_{x\in V^{(k)}} P(x\mid x_{1:i-1})$

然后“**the distribution is then re-scaled as in equation 3**”。

而 equation (3) 是：

$$
P'(x\mid x_{1:i-1}) =
\begin{cases}
P(x\mid x_{1:i-1})/p' & x \in V^{(k)} \\
0 & \text{otherwise}
\end{cases}
$$

所以答案是：

> **是的，top-k 在截断掉 $k$ 之外的 token 后，会对剩余 token 的概率重新归一化，再进行采样。**

***

### 4) 举个简单例子

假设某一步模型给出：

| token | 原始概率 |
| ----- | ---- |
| A     | 0.40 |
| B     | 0.30 |
| C     | 0.15 |
| D     | 0.10 |
| E     | 0.05 |


如果设 $k=3$，那么只保留 A、B、C：

*   保留总质量：

$$
p' = 0.40+0.30+0.15=0.85
$$

重新归一化后：

*   $P'(A)=0.40/0.85 \approx 0.471$
*   $P'(B)=0.30/0.85 \approx 0.353$
*   $P'(C)=0.15/0.85 \approx 0.176$
*   $P'(D)=0$
*   $P'(E)=0$

然后从 $\{A,B,C\}$ 中按这个新分布采样。

***

### 5) 为什么要重新归一化？

因为截断后，保留的概率和不再是 1，而是 $p' < 1$。\
如果不归一化，就不是一个合法概率分布，没法直接采样。

同时这也是论文指出 top-k 的一个问题：

*   如果  $k$  设得太大

*   一些原本概率很小、但挤进 top-k 的 token

*   会因为重新归一化而**相对权重被放大**

*   可能导致不连贯

这也是论文更推崇 **top-p / nucleus sampling** 的原因：\
它不是固定保留 $k$ 个，而是保留累计概率达到 $p$ 的那部分 token，更动态。

***

### 6) top-k 和 beam search 的根本区别

| 方法               | 是否随机 | 核心目标                  |
| ---------------- | ---- | --------------------- |
| Beam search      | 否    | 找高概率序列                |
| Top-k sampling   | 是    | 在高概率 token 中随机采样      |
| Nucleus sampling | 是    | 在累计概率达到 $p$ 的动态候选集中采样 |


所以：

*   **beam search** = 搜索最优
*   **top-k** = 截断后采样
*   **top-p** = 动态截断后采样

## beam search岂不是意味着需要有b个并行采样的分支，每次生成新的token时需要进行b次推理计算？导致其解码方法相比其他方法消耗大量内存带宽与算力？

***

是的，**总体上可以这么理解**：\
**beam search 比 greedy / top-k / top-p 这类“单分支解码”更贵**，因为它需要同时维护 $b$ 个候选序列（beams），每一步都要对这 $b$ 个前缀分别继续打分与筛选。

但更准确地说，不一定是“做了 $b$ 次完全独立推理”，而是：

> **每一步需要对 beam 中的 $b$ 个活跃前缀都计算下一 token 分布**，因此其计算、KV cache、内存访问通常都会随 beam size $b$ 近似线性增长。

***

### 1. 你的直觉为什么是对的

假设 beam width 是 $b$。

在时刻 $t$：

*   greedy / top-k / top-p

只维护 **1 个当前前缀**

*   beam search

维护 **$b$ 个当前前缀**

那么下一步时，模型要基于这 $b$ 个前缀分别算：

$$
P(x_t \mid x_{<t}^{(1)}), \;
P(x_t \mid x_{<t}^{(2)}), \;
\ldots,\;
P(x_t \mid x_{<t}^{(b)})
$$

所以从逻辑上说，确实相当于有 **$b$ 条并行分支**在扩展。

***

### 2. 为什么它更耗算力

#### 单分支采样

对 top-k / top-p：

*   每步只要算一次 logits
*   然后做截断、归一化、采样
*   计算重点在 **模型前向传播**

#### beam search

每步要：

1.  对  $b$  个 beam 都算一次下一步 logits

2.  对每个 beam 取若干高分 token

3.  把所有候选合并后再排序

4.  选出新的前  $b$  个 beam

所以额外开销包括：

*   **更多前向计算**
*   **更多 KV cache**
*   **更多候选分数排序**
*   **更多内存读写和重排**

因此实际推理代价通常显著更高。

***

### 3. 为什么也更耗内存 / 显存

这是很关键的一点。

Transformer 自回归生成时，通常会缓存每层的 **KV cache**。\
如果你只有 1 个分支，就只需要维护 1 份当前序列对应的 cache。

但 beam search 要维护 **$b$ 个不同前缀**，因此通常需要：

*   为每个 beam 维护一套状态

*   或者至少维护相当于  $b$  倍 batch 的 cache

所以显存/内存占用大致会随着 beam size 增长。

尤其在长文本生成时，KV cache 本来就是大头，beam search 会让这个问题更明显。

***

### 4. 不是“完全独立做 b 次推理”，而是“batch 化的 b 个前缀”

实践中实现 beam search 时，通常不会真的串行地：

*   先算 beam 1
*   再算 beam 2
*   再算 beam 3

而是会把这 $b$ 个 beam 当成一个 **batch** 一起送进模型。

所以更准确说法是：

*   **不是做 $b$ 次完全独立的推理调用**

*   而是做 **1 次 batch size = $b$ 的前向**

*   但其总 FLOPs、cache 占用、带宽压力依然接近  $b$  倍增长

因此你的核心判断是对的，只是实现上往往是**并行 batch 化**而不是“手工 b 次单独调用”。

***

### 5. 与 top-k / top-p 的复杂度差异

#### top-k / top-p

每一步：

*   1 个前缀

*   1 次前向

*   再做一个轻量的后处理：

*   top-k：取前  $k$

*   top-p：累计概率截断

*   然后采样

#### beam search

每一步：

*   $b$  个前缀

*   相当于 batch size  $b$  的前向

*   还要做：

*   每个 beam 的候选扩展

*   合并候选

*   全局排序/筛选 top- $b$

*   beam 重排

*   cache reorder

因此 beam search 的开销不只是模型前向翻倍，还多了不少**调度与内存操作**。

***

### 6. 为什么说 beam search 尤其“吃内存带宽”

在现代 LLM 推理里，单 token 解码往往不是纯算力瓶颈，而常常是：

*   **KV cache 读写**
*   权重读取
*   张量搬运
*   beam reorder

beam search 恰好会恶化这些：

#### 原因 1：KV cache 变大

每个 beam 都要有状态，cache 总量变大。

#### 原因 2：beam 重排

每一步选出新的 top-$b$ beam 后，往往需要：

*   重排 beam 的 hidden state / cache 索引
*   做 gather / scatter

这类操作对带宽不友好。

#### 原因 3：batch 变大但每步仍是 token-by-token

虽然 batch 化了，但自回归解码仍然一次只生成一个 token，导致：

*   并行度有限
*   memory-bound 特性明显

所以工程上 beam search 确实往往比采样法更“重”。

***

### 7. 这也是开放式生成里 beam search 不受欢迎的原因之一

这篇论文主要批评的是 **质量问题**：

*   beam search 会退化
*   容易重复
*   概率虽高，但文本不自然

但从工程角度，它还有第二个缺点：

*   **更贵**
*   **更慢**
*   **更占显存/内存**
*   结果还往往不如 top-p\*\*

所以在现代大语言模型开放式生成中，大家普遍更喜欢：

*   **top-p / nucleus sampling**
*   或 top-k + temperature
*   或更复杂的 sampling-based decoding

而不是 beam search。

***

### 8. 什么时候 beam search 仍然有价值？

虽然它贵，但在某些任务里还是常用：

*   机器翻译
*   摘要
*   语音识别
*   受约束生成
*   结构化输出

因为这些任务：

*   输出空间更受限
*   “高概率解”通常更合理
*   需要更稳定、更可控的搜索

而不是像故事续写、自由问答这类开放式任务那样，允许很多合理答案。

***

### 9. 一个简化比较

假设生成长度为 $T$，beam width 为 $b$。

#### 单分支采样

每步大约：

*   1 次模型前向

*   总成本约为  $O(T)$  次单前缀解码

#### beam search

每步大约：

*   $b$  个前缀同时解码

*   总成本近似为  $O(T \cdot b)$  级别

当然实际不一定严格线性，因为：

*   batch 并行可能提高硬件利用率
*   共享前缀在某些实现里可部分复用
*   early stopping 可能提前结束部分 beam

但**数量级上它就是更贵的**。

***

### 10. 结论

你的理解基本正确，可以表述为：

> **Beam search 需要同时维护 $b$ 个候选分支，因此每一步都要对这 $b$ 个分支计算下一 token 分布。实际实现通常会把它们 batch 化并行处理，但整体算力、KV cache、内存带宽和重排开销通常都会随 beam size 近似线性增加，所以相比 top-k/top-p 等单分支采样方法更昂贵。**

而且结合这篇论文的结论：

> **它不仅更贵，在开放式文本生成里质量往往还更差。**

### 一、 为什么传统的单一策略（如单纯的 Top-P）不够用？

传统的解码策略通常是在 **Temperature -> Top-K -> Top-P** 之间做简单选择，但这种设计存在两个致命缺陷：

1.  **Top-P 的“置信度盲区”**： Top-P（核采样）是累积概率截断。

    *   **当模型极度自信时**（例如生成代码、数学计算或常用词）：前一两个 Token 的概率可能就已经达到了 99%。此时 Top-P=0.9 会直接退化为 Greedy Search，失去多样性。
    *   **当模型极度不确定时**（例如面对开放性创作）：分布可能非常扁平，前 100 个 Token 的概率可能都在 1% 左右。此时 Top-P=0.9 会放进来将近 90 个极低概率的“噪声 Token”，导致模型开始胡言乱语。

2.  **局部极小值与“话痨循环”（Repetition Loop）**： 自回归模型很容易陷入局部循环。一旦模型在上下文中生成了相似的短语，注意力机制就会自我强化，不断重复相同的句子。单纯的概率截断无法解决这种由于注意力退化带来的循环问题。

***

### 二、 2026年主流的组合采样链（Sampler Chain）

在实际推理中，Logits（模型输出的未归一化概率得分）要经历一整套像流水线一样的“过滤器”处理。以目前业界常用的 `llama.cpp` 或 `vLLM` 的标准流水线为例，它的完整组合通常包含以下几类策略：

```
原始 Logits 
   ⬇
1. 惩罚器阶段 (Penalties / DRY)  --> 抑制重复，打破循环
   ⬇
2. 约束器阶段 (Grammar / Schema) --> 强制符合格式要求（如 JSON）
   ⬇
3. 截断器阶段 (Min-P / Top-A)    --> 根据模型置信度动态保留候选词
   ⬇
4. 创意器阶段 (XTC)              --> 偶尔屏蔽最明显的词，激发新词
   ⬇
5. 缩放与采样 (Dynamic Temp)     --> 调整概率分布，完成最终采样
```

#### 1. 惩罚器：防重复的进阶（DRY Sampler 机制）

传统的惩罚机制（如 `repetition_penalty`）是全局无脑地降低已出现词的概率，这往往会导致模型为了“避开惩罚”而写出语法不通的句子。

*   **DRY (Don't Repeat Yourself) 采样器**：这是近年来在开源社区和推理引擎中被广泛采用的技术。它不同于简单地惩罚单个 Token，而是检测**N-gram（短语组合）的重复**。当生成的序列接近上下文中已有的某个短语时，DRY 会根据匹配的长度，指数级地对即将生成的下一个 Token 施加惩罚，完美解决了“车轱辘话”问题，且不伤害句子的基本语法结构。

#### 2. 约束器：结构化解码（Grammar / Schema Constrained Decoding）

在企业 Agent 应用中，格式 compliance（合规性）压倒一切。

*   在概率采样前，推理引擎（例如 vLLM 的 `Outlines` 库或 llama.cpp 的语法解释器）会引入**上下文无关文法（CFG）或 JSON Schema 掩码**。
*   如果当前必须输出一个 `"` 或者 `,`，非此格式的 Token 的 Logits 就会被强制设为 \$-\infty\$。这种“硬截断”与概率采样策略结合，保证了模型在保持一定创造力的同时，绝对不会破坏 JSON 结构。

#### 3. 自适应截断：Min-P 与 Top-A 的崛起

这是取代传统 Top-P 的关键策略。

*   **Min-P 采样**：其核心思想是，**截断阈值应该与模型“最自信的那个词”的概率挂钩**。 \$ $\text{阈值} = P_{\text{max}} \times \text{Scale}$ \$ 如果最自信的词概率是 0.9（模型很确定），那么只有概率大于  $0.9 \times 0.1 = 0.09$  的词才会被保留。 如果最自信的词概率只有 0.1（模型很迷茫），那么概率大于  $0.1 \times 0.1 = 0.01$  的词都可以被考虑。 这让模型在确定的地方非常严谨，在不确定的地方又能表现出自然的创造力，不容易“发疯”。

*   **Top-A 采样**：根据最高概率的平方进行自适应截断。在 MoE（混合专家模型）中表现尤为亮眼，能极大地过滤掉 MoE 分布里无意义的长尾概率。

#### 4. 创意干预：XTC (Exclude Top Choices) 采样器

在写作、角色扮演或头脑风暴任务中，模型很容易陷入陈词滥调（例如高频出现一些所谓的“GPT流行语”）。

*   **XTC 采样器**：在一定概率（XTC Probability）和阈值（XTC Threshold）下，**故意屏蔽概率最高的那个（或几个）Token**，强制模型去选择概率稍低、但依然合理的“同义词”或“非常规词”。
*   这种策略既不会导致语句不通顺（因为被选中的依然是概率较高的候选词），又能有效打破模型的语言模式惯性，使得生成内容更加具有文学感和新意。

#### 5. 动态温度控制：Dynamic Temperature

传统 Temperature 在生成全过程中是一个固定值。

*   **Dynamic Temperature** 会根据当前 Logits 分布的**信息熵**（即模型的迷茫程度）动态调整温度。
*   当模型处于逻辑严密段落时（信息熵低），自动调低温度以确保准确性；在需要自由发挥的过渡段落（信息熵高），自动调高温度以丰富语言表现。

***

### 三、 为什么这些策略需要进行“链式”组合？

这几种策略并存，并且需要以**特定的先后顺序**执行（例如 llama.cpp 的经典排序：`Penalties -> DRY -> Grammar -> Top-K -> Top-P -> Min-P -> XTC -> Temperature`），其背后的核心逻辑在于：

1.  **先做“硬过滤”，再做“软调整”**： 如果先调整 Temperature，Logits 的相对大小就会被扭曲，这会让后续的 Min-P 或 Top-P 的截断标准失效。因此，必须先通过 DRY 剔除重复词，通过 Grammar 剔除不合格式的词，再进行概率截断，最后才用 Temperature 调整剩下安全词的“浓度”。

2.  **多维度协同管理信息熵**：

    *   DRY 负责**时序逻辑维度**（不要前后重复）。
    *   Min-P 负责**横向概率维度**（不要混入无关噪声）。
    *   XTC 负责**风格审美维度**（不要千篇一律）。
    *   Grammar 负责**业务规范维度**（不要偏离格式要求）。

### 总结

在目前的推理大后端中，解码不再是“调高温度多点创造力，调低温度多点准确性”的简陋游戏。实际推理是通过**把惩罚、语法约束、自适应截断和创意干预策略串联起来**，实现对大模型输出概率分布在**时序、语法、语义及风格**上的全方位重塑。
